# Sac de voyage

Le besoin est cadré. L'application n'est pas encore construite.

Elle est générale et démarre vide. On l'ouvre soi-même. Rien ne dit de prendre un sac.

## Deux étages

Un modèle décide. Un enfant porte le nom qu'on lui donne.

- Modèle de sac : ce qui doit être dedans. On ne coche pas ici.
- Enfant de sac : une fois, ou récurrent. On ouvre, on voit tout, on coche.
- Modèle de départ : quels sacs, et quelles actions en J-x.
- Enfant de départ : une fois, ou récurrent. On choisit un sac, puis on voit son contenu.

Un enfant peut ajouter une affaire ou changer un nombre. Le reste suit le modèle. Un changement de nom d'objet suit partout. Le nombre reste propre à chaque sac.

## Départ

Une fois : une date de début et une date de fin. Les J-x se comptent depuis le début.

Récurrent : pas de dates à saisir. Le jour de la règle est le jour.

## Après usage

À la création du sac, trois réglages.

- Il reste prêt.
- Tout sortir après la fin.
- Sortir seulement les affaires marquées.

Après la sortie, on ne voit que ce qui doit sortir. Le retour à « rempli » est manuel.

## Agenda

Un agenda à part, seulement pour les J-x. Jamais pour dire quoi prendre.

L'action apparaît tous les jours à partir de sa date, jusqu'à ce que la case soit cochée. Le jour qui passe ne la supprime pas. La fois suivante d'une action récurrente n'est créée que lorsque la précédente est cochée.

## Dehors

Pas de partage. Pas d'animal. Pas d'intelligence artificielle. Pas d'écran « prends le sac ».
